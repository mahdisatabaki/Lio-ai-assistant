# تحلیل چالش سوم هکاتون لیارا — از چت‌بات مستندات تا سیستم کاهش تیکت

> نسخه‌ی ۲ — بازنویسی‌شده پس از دریافت صورت‌مسئله‌ی واقعی کسب‌وکار.
> منابع: ویدیوی معرفی چالش + بررسی مستقیم مستندات، مخزن و زیرساخت لیارا.

---

## خلاصه‌ی اجرایی

لیارا حجم بالای تیکت پشتیبانی دارد و **دو علت** برایش شناسایی شده: کاربر یا مستندات را پیدا نکرده، یا پیدا کرده و نفهمیده. متریک موفقیت این چالش «کیفیت پاسخ» نیست — **کاهش تیکت** است.

نتیجه‌ی کلیدی این تحلیل:

> **یک چت‌بات RAG فقط علت اول را حل می‌کند. علت دوم را تقریباً اصلاً حل نمی‌کند.**

بنابراین محصول پیشنهادی یک چت‌بات نیست؛ سیستمی است با سه نقطه‌ی مداخله در چرخه‌ی حیات تیکت (پیشگیری، رفع، تحویل هوشمند) به‌علاوه‌ی یک حلقه‌ی بازخورد که خودِ مستندات را اصلاح می‌کند.

## بخش ۱ — بازتعریف مسئله

### ۱.۱ دو علت، دو مسئله‌ی متفاوت

| علت تیکت | ماهیت واقعی مشکل | چت‌بات RAG حلش می‌کند؟ |
|---|---|---|
| **داکیومنت را پیدا نکرده** | مشکل **توزیع** — اطلاعات هست، به دست کاربر نمی‌رسد | ✅ تا حد خوبی |
| **داکیومنت را نفهمیده** | مشکل **ترجمه** — اطلاعات رسیده، اما به وضعیت کاربر ترجمه نشده | ❌ تقریباً هیچ |

### ۱.۲ چرا چت‌بات علت دوم را حل نمی‌کند

هسته‌ی استدلال:

> کاربر صفحه‌ی مستندات را **خوانده** و **نفهمیده**.
> حالا چت‌بات همان صفحه را بازیابی می‌کند و **بازنویسی‌شده** تحویلش می‌دهد.
> **همان شکست، در یک حباب چت.**

مستندات ذاتاً **عمومی** نوشته می‌شوند؛ وضعیت کاربر **خاص** است. شکاف، شکافِ «نرسیدنِ اطلاعات» نیست — شکافِ «اعمال‌نشدنِ اطلاعات روی مورد من» است.

### ۱.۳ جهت حرکت محصول

```
از  «بهت می‌گم کجا نوشته»                        ← جستجو
از  «بهت می‌گم چی نوشته»                         ← چت‌بات RAG (اکثر تیم‌ها اینجا می‌ایستند)
به  «برای پروژه‌ی تو انجامش می‌دم و مطمئن می‌شم کار کرد»  ← عامل (Agent)
```

## بخش ۲ — تشخیص: مستندات دقیقاً کجا کاربر را زمین می‌زند

مستندات لیارا **بد نیست** — کامل و مرتب است. مشکل این است که **ساختار مستندات با ساختار ذهن کاربر یکی نیست.** پنج شکست ساختاری، همه با داده تأیید شده:

### شکست ۱ — چیده‌شده بر اساس «سرویس»، کاربر بر اساس «کار» فکر می‌کند
«دیپلوی سایت لاراول با دیتابیس و دامنه» یعنی ۴ صفحه در ۳ سرویس مختلف (`paas/laravel`، `dbaas/mysql`، `paas/domains`، `dns`). هیچ صفحه‌ای این سفر را یک‌جا ندارد. کاربر باید خودش پازل را بچیند — و نمی‌داند چند تکه دارد.

### شکست ۲ — کاربر با «خطا» می‌آید، نه با «کلیدواژه»
۴۵ صفحه‌ی `fix-common-errors` وجود دارد. اما کاربر یک استک‌تریس دارد، نه عبارت جستجو. و بدتر:

> **خطای CORS به‌تنهایی ۱۵ صفحه‌ی جداگانه دارد** — Django، Flask، Laravel، .NET، PHP، Python + هشت فریم‌ورک Node (Express، NestJS، Fastify، Koa، Hapi، Nuxt، Adonis، Strapi).

کاربر سرچ می‌کند «CORS»، ۱۵ نتیجه‌ی تقریباً هم‌شکل می‌گیرد و **نمی‌داند کدام مالِ اوست**. بدترین حالت ممکن: هم اطلاعات هست، هم کاربر شکست می‌خورد. همین الگو برای `WORKER TIMEOUT` (۳ صفحه)، «محدودیت آپلود» (۵ صفحه) و `Multiple Settings Files` (۲ صفحه) تکرار می‌شود.

### شکست ۳ — تکرار محتوا اعتماد را می‌شکند
عناوین کاملاً یکسان زیر دو مسیر مختلف: `paas/django/fix-common-errors/cors.md` و `paas/python/fix-common-errors/cors.md`. کاربر دو نتیجه‌ی یکسان می‌بیند و شک می‌کند کدام به‌روزتر است.

### شکست ۴ — دانش عملیاتی صفحه‌به‌صفحه تکه‌تکه شده
بیش از ۴۰ صفحه‌ی CLI که هرکدام **فقط یک دستور** دارد (`create-app`، `delete-db`، `resize-db`، `add-or-edit-envs`…). کاربر می‌خواهد دستورش را یادش بیاید، نه اینکه صفحه باز کند.

### شکست ۵ — بخش «میرورها»: درد کاملاً ایرانی، دفن‌شده در ته مستندات
۲۱ صفحه برای npm، pypi، composer، go، nuget، Docker Hub، GHCR، Quay، MCR، k8s و ۱۱ توزیع لینوکس. یکی از **پرتکرارترین** دلایل شکست build برای توسعه‌دهنده‌ی ایرانی — و کاربر تازه‌کار اصلاً نمی‌داند کلمه‌ی «میرور» را باید سرچ کند. او فقط `npm ERR! network` می‌بیند. این مصداق خالص «داکیومنت را پیدا نکرده» است.

> **جمع‌بندی تشخیص:** مشکل «نبودِ اطلاعات» نیست. فاصله‌ی بین **وضعیت کاربر** و **صفحه‌ی درست** است. محصول باید «مترجمِ وضعیت کاربر به اقدام» باشد، نه «سرچ بهتر».

## بخش ۳ — زیرساخت و داده‌ی در دسترس

### ۳.۱ کشف کلیدی: corpus از قبل آماده است

لیارا یک منبع داده‌ی تمیز و ماشین‌خوان منتشر کرده:

- **فهرست کامل صفحات:** [`docs.liara.ir/all-links-llms.txt`](https://docs.liara.ir/all-links-llms.txt) → **۱۱۴۲ صفحه**، فرمت `- [عنوان فارسی](URL)`
- **نسخه‌ی Markdown تمیز هر صفحه:** `https://docs.liara.ir/llms/{service}/{category}/{page}.md`

**توزیع محتوا:**

| سرویس | صفحه | سرویس | صفحه |
|---|---|---|---|
| `paas` | ۴۲۵ | `references` (API/CLI) | ۶۵ |
| `one-click-apps` | ۱۸۹ | `email-server` | ۳۸ |
| `dbaas` | ۱۶۷ | `object-storage` | ۳۴ |
| `ai` | ۱۲۷ | `mirrors` | ۲۱ |
| `iaas` | ۶۶ | `dns` + `overview` | ۱۰ |

**اندازه‌ی corpus:** میانگین ۵.۱ کیلوبایت هر صفحه → **~۵.۹ مگابایت مارک‌داون ≈ ۱.۳ تا ۲ میلیون توکن فارسی**. کل corpus در context جا نمی‌شود → RAG اجباری است.

**مسیر URL = متادیتای رایگان:** `paas/django/how-tos/connect-to-db/postgresql.md` بدون هیچ پردازشی سه فیلتر (سرویس/پلتفرم/موضوع) می‌دهد.

**الگوی خودِ لیارا:** پوشه‌ی `indexer/` در مخزن مستندات کراولر جداگانه برای هر سرویس دارد (`paas.js`, `dbaas.js`, `ai.js`, …) به‌علاوه‌ی `utils/stopWords.js`، `utils/synonyms.js` و `services/meilisearch.js`. یعنی جستجوی خود لیارا روی **Meilisearch** با استاپ‌ورد و مترادف فارسی سفارشی کار می‌کند — یک نقشه‌ی راه رایگان برای لایه‌ی lexical.

### ۳.۲ سرویس‌های لیارا که برای این پروژه در دسترس‌اند (تأیید شده)

| نیاز | سرویس | جزئیات |

→ کل استک را می‌شود ۱۰۰٪ روی لیارا زد.

## بخش ۵ — سولوشن‌ها

### 🥇 S1 — «همراه استقرار» (Deployment Companion)

**علت هدف:** ۲ (نفهمیدن) + پیشگیری از تیکت

آنچه آن را از چت‌بات جدا می‌کند: **«حالت» (State)**. این چت نیست؛ یک **فرآیند با حافظه** است.

```
┌── نقشه‌ی استقرار پروژه‌ی شما ────────────────┐
│ ✅ ۱. ساخت برنامه            انجام شد        │
│ ✅ ۲. تنظیم liara.json       انجام شد        │
│ 🔵 ۳. اتصال دیتابیس          ← الان اینجایی  │
│ ⚪ ۴. متغیرهای محیطی                          │
│ ⚪ ۵. دیپلوی                                  │
│ ⚪ ۶. دامنه و SSL                             │
└──────────────────────────────────────────────┘

لیارایار: قدم ۳ — دیتابیس پستگرس‌ات ساخته شد.
حالا این متغیر رو باید به برنامه بدی:
  [بلوک کد آماده با مقادیر پرشده]

⚡ اجرا کن و خروجی رو همین‌جا بچسبون تا تأیید کنم.
```

**چهار چیزی که چت‌بات ندارد و این دارد:**

1. **یک قدم در لحظه** — کاربر با دیوار متن مواجه نمی‌شود (علت اصلی «نفهمیدم»)
2. **حلقه‌ی تأیید** — تا نتیجه‌ی قدم فعلی را نبیند، قدم بعد را نمی‌دهد؛ دقیقاً کاری که پشتیبان انسانی می‌کند
3. **حافظه‌ی بین‌جلسه‌ای** — فردا برمی‌گردد و از قدم ۳ ادامه می‌دهد
4. **خروجی artifact** — `liara.json` واقعی، نه توصیفِ `liara.json`

**چرا اول:** تنها سولوشنی که **تیکت را قبل از تولد می‌کشد**. بقیه بعد از گیر کردن وارد می‌شوند؛ این نمی‌گذارد گیر بیفتد. ضمناً بیشترین امتیاز Agentic را می‌گیرد (سؤال تکمیلی + چندمرحله‌ای + حفظ context + قدم بعدی، همه در یک فیچر).

### 🥈 S2 — «عیب‌یاب» (Diagnostic Agent)

**علت هدف:** ۱ و ۲ هر دو

ورودی، سؤال نیست — **لاگ خطاست**. کاربر گیرکرده کلیدواژه ندارد، ولی همیشه استک‌تریس دارد.

تفاوت کلیدی با چت‌بات: **فرضیه‌ی چندگانه با اولویت.**

```
لیارایار: از لاگ فهمیدم Laravel + خطای 502.
سه علت محتمل، به ترتیب احتمال:

  ۱️⃣ TrustedProxies تنظیم نشده  (۶۰٪)  ← از این شروع کنیم
  ۲️⃣ پورت اشتباه در liara.json  (۲۵٪)
  ۳️⃣ کمبود رم پلن               (۱۵٪)

بریم سراغ اولی: [راهکار + کد]
جواب نداد؟ بگو «نشد» تا بریم سراغ دومی.
```

**چرا کار می‌کند:** خطای CORS ۱۵ صفحه‌ی جداگانه دارد؛ کاربر سرچ می‌کند و ۱۵ نتیجه‌ی هم‌شکل می‌گیرد. عیب‌یاب فریم‌ورک را **از خودِ استک‌تریس** تشخیص می‌دهد و یکی را انتخاب می‌کند.

**زیرحالت طلایی — میرورها:** لاگ شامل `npm ERR! network` یا `ETIMEDOUT` → مستقیم به تنظیم میرور. کاربر تازه‌کار نمی‌داند باید کلمه‌ی «میرور» را سرچ کند؛ محصول این را برایش پل می‌زند.

### 🥉 S3 — «سد تیکت» (Ticket Deflection Layer)

> از نظر تجاری، هوشمندانه‌ترین سولوشن کل لیست.

**علت هدف:** هر دو — در آخرین لحظه‌ی ممکن

**جایگذاری:** دقیقاً روی **فرم ساخت تیکت**. کاربر عادت دارد مشکلش را به زبان طبیعی و مفصل بنویسد — کاری که در آن *خوب* است. همان متن، بهترین ورودی ممکن برای LLM است.

```
[کاربر در حال نوشتن تیکت...]
"سلام، اپ جنگوم رو دیپلوی کردم ولی فایل‌های 
 استاتیک لود نمیشن و CSS نداره..."

        ↓  (قبل از دکمه‌ی ارسال)

💡 فکر کنم بتونم همین الان حلش کنم:
   علت: collectstatic اجرا نشده
   [راهکار + کد + منبع]
   
   [ ✅ حل شد، تیکت نمی‌خوام ]   [ ❌ حل نشد، تیکتم رو بفرست ]
```

**سه دلیل قدرت:**

1. **تنها سولوشنی که KPI کسب‌وکار را مستقیماً اندازه می‌گیرد:** «۳۸٪ تیکت‌های در حال نگارش، قبل از ارسال حل شدند» — عدد قابل ارائه به داور و به لیارا.
2. **حتی وقتی شکست می‌خورد ارزش تولید می‌کند:** اگر نتوانست حل کند، **تیکت غنی‌شده** می‌سازد — استک، نسخه، لاگ، مستنداتی که چک شد، راهکارهایی که امتحان شد. پشتیبانی به جای «سلام مشکل دارم» یک گزارش کامل می‌گیرد. **زمان حل تیکت هم کم می‌شود، نه فقط تعدادش.**
3. **دموی فوق‌العاده:** داور نوشتن یک تیکت و منحرف‌شدنش را جلوی چشمش می‌بیند.

### S4 — «چرخه‌ی اصلاح مستندات» (Docs Gap Flywheel)

> این سولوشن مسئله را درمان می‌کند، نه مسکن بدهد.

**علت هدف:** ریشه‌ی هر دو علت — کیفیت خودِ مستندات

هر شکستِ دستیار = یک نقص مستندات. جمع، خوشه‌بندی و گزارش به لیارا:

```
📊 داشبورد شکاف مستندات — این هفته

🔴 ۴۷ کاربر  · «اتصال Next.js به Redis»
   → صفحه وجود دارد ولی هیچ‌کس پیدایش نکرد
   💡 پیشنهاد: افزودن کلیدواژه‌های «کش» و «session» به عنوان

🔴 ۳۱ کاربر  · «محدودیت آپلود در Next.js»
   → صفحه اصلاً وجود ندارد (فقط برای Laravel/PHP/Django هست)
   💡 پیشنهاد: [پیش‌نویس صفحه‌ی جدید — آماده‌ی PR]

🟡 ۱۹ کاربر  · «CORS» → از ۱۵ صفحه، ۱۲ بار اشتباه انتخاب شد
   💡 پیشنهاد: یک صفحه‌ی مادر با انتخابگر فریم‌ورک
```

**چرا متمایزکننده است:** بقیه‌ی تیم‌ها چت‌باتی تحویل می‌دهند که تیکت را کم می‌کند. شما سیستمی تحویل می‌دهید که **باعث می‌شود مستندات هر هفته بهتر شود** — یعنی نیاز به تیکت به‌مرور از بین می‌رود. حلقه‌ی مرکب.

نسخه‌ی حداکثری (اگر وقت شد): پیش‌نویس صفحه‌ی گمشده را به‌صورت PR به `liara-cloud/docs` بفرستد.

### S5 — «دستیار متصل به حساب» (Account-Aware Agent)

**علت هدف:** ۲ — بالاترین سطح شخصی‌سازی ممکن

لیارا API عمومی دارد (`https://api.iran.liara.ir`، احراز هویت `Bearer`). یعنی دستیار می‌تواند به‌جای حدس زدن، **وضعیت واقعی** را بخواند:

```
کاربر: چرا اپم بالا نمیاد؟

لیارایار: [برنامه‌ات رو چک کردم]
  🔍 اپ shop-api روی پلن «کوچک» (۲۵۶MB رم)
  🔍 متغیر DATABASE_URL ثبت نشده
  🔍 آخرین دیپلوی: ۲ ساعت پیش، وضعیت crash

  علت: برنامه بدون DATABASE_URL بالا نمیاد.
  [دستور آماده برای ثبتش]
```

**تفاوت ماهوی:** این دیگر بازیابی مستندات نیست — **عمل روی وضعیت واقعی** است. تعریف دقیق Agentic.

**ریسک (صادقانه):** توکن کاربر دست شماست. اگر ساختید:
- فقط **read-only**؛ هیچ عملیات نوشتنی بدون تأیید صریح کاربر
- توکن فقط در session، رمزنگاری‌شده، هرگز در لاگ
- در دمو با حساب آزمایشی

اگر وقت کم است **نسازید** — ریسک امنیتی می‌تواند ۵۰ امتیاز معیار چهارم را بسوزاند. اما اگر ساختید، تنها تیمی خواهید بود که دستیارش واقعاً کاری *انجام* می‌دهد.

---

### S6 — «حضور در محل حادثه» (Distribution)

**علت هدف:** ۱ — در ریشه‌اش

کاربر مستندات را پیدا نمی‌کند چون **اصلاً به `docs.liara.ir` نمی‌رود**؛ در ترمینال یا ادیتورش گیر کرده. پس دستیار را ببر آنجا: خروجی MCP برای Cursor/Claude Code، یا `liara ask "..."` در CLI.

**اما:** خروجی چالش «لینک دیپلوی‌شده» است. این را **بونوس** بگیر، نه هسته — یک تب «اتصال به ادیتور» با تنظیمات MCP و دموی کوتاه کافی است.

## بخش ۶ — ترکیب: یک محصول، نه شش تا

همه در **یک وب‌اپ دیپلوی‌شده** جمع می‌شود. نام پیشنهادی: **«لیارایار»**

```
┌─────────────────────────────────────────────────────┐
│  🎯 پروژه‌ی من: Django · Postgres · پلن کوچک   ✏️  │
├─────────────────────────────────────────────────────┤
│                                                     │
│   سؤالت رو بپرس، لاگ خطات رو بچسبون،                │
│   یا بگو می‌خوای چی رو راه بندازی                    │
│                                                     │
│   [ 🚀 تازه شروع کردم ]  [ 🐛 خطا خوردم ]           │
│   [ 📝 می‌خوام تیکت بزنم ]                           │
└─────────────────────────────────────────────────────┘
         │              │                │
        S1             S2               S3
   همراه استقرار    عیب‌یاب          سد تیکت
         └──────────────┴────────────────┘
                        ▼
              S4 · داشبورد /insights
```

**تشخیص خودکار مسیر بر اساس شکل ورودی:**

| ورودی کاربر | مسیر فعال |
|---|---|
| متن چندخطی با `Error` / `Traceback` / `ERR!` | S2 — عیب‌یاب |
| «می‌خوام … رو راه بندازم» | S1 — همراه استقرار |
| متن روایی و طولانی (شبیه تیکت) | S3 — سد تیکت |
| لینک ریپو یا `package.json` / `composer.json` | S1 — تولید liara.json |
| `Procfile` / `docker-compose.yml` | مترجم مهاجرت |
| سؤال کوتاه تعریفی | پاسخ ساده + منبع |

کاربر هیچ دکمه‌ای نمی‌زند — محصول می‌فهمد. این خودش نمایش زنده‌ی «درک صحیح Intent» است.

### لایه‌های مشترک روی همه‌ی مسیرها

- **کارت پروژه‌ی من** — چیپ همیشه‌حاضر و قابل‌ویرایش: `Next.js 16 · PostgreSQL · پلن سبک`. همه‌ی پاسخ‌ها پیش‌فیلتر می‌شوند. شخصی‌سازی را **قابل‌مشاهده** می‌کند (اکثر تیم‌ها آن را پنهان می‌گذارند و داور نمی‌بیند) و هزینه‌ی توکن را هم کم می‌کند.
- **لایه‌ی اعتماد** — کارت منبع کلیک‌پذیر زیر هر پاسخ + بج «۳ روز پیش به‌روز شده» + نمایش «در حال خواندن ۳ صفحه…» + **حالت صریح «نمی‌دانم»**:

```
کاربر: قیمت پلن تورینگ چنده؟

لیارایار: این عدد در مستندات نیست — قیمت‌ها در صفحه‌ی تعرفه‌ها 
نگهداری می‌شود و ممکن است تغییر کند.
آنچه مستندات می‌گوید: پلن تورینگ برای پروژه‌های سازمانی، دسترسی 
کامل به مدل‌ها + پردازش تصویر + نگهداری طولانی‌تر لاگ.
🔗 قیمت به‌روز: liara.ir/pricing
```

- **چیپ‌های قدم بعدی** — بعد از هر پاسخ ۲ تا ۳ پیشنهاد زمینه‌ای. ارزان‌ترین امتیاز کل پروژه.

## بخش ۷ — نگاشت به ۳۰۰ امتیاز داوری

| معیار | امتیاز | چه چیزی آن را می‌گیرد |
|---|---|---|
| **کیفیت و صحت پاسخ‌ها** | ۸۰ | S2 (تشخیص از لاگ = دقت بالا) + Hybrid retrieval + منبع اجباری + حالت صریح «نمی‌دانم» |
| **طراحی UI و UX** | ۵۵ | نقشه‌ی استقرار بصری S1، کارت منابع، RTL درست، بلوک کد LTR با دکمه‌ی کپی، responsive |
| **Agentic و Personalization** | ۵۰ | S1 (چندمرحله‌ای + سؤال تکمیلی + حافظه) + کارت پروژه + S5 (عمل روی وضعیت واقعی) |
| **امنیت، پایداری، Monitoring** | ۵۰ | Rate limit با Redis، کلید فقط سمت سرور، مدیریت خطا، **داشبورد S4 خودش Monitoring است** |
| **استقرار روی لیارا** | ۴۰ | کل استک روی لیارا: PaaS + Postgres/pgvector + Redis + سرویس AI |
| **بهینه‌سازی هزینه** | ۲۵ | کش پاسخ، فیلتر متادیتا، مسیریابی مدل (ساده→ارزان، پیچیده→قوی)، **نمایش شفاف مصرف توکن در UI** |

**نکته‌ی طلایی:** داشبورد S4 هم‌زمان امتیاز Monitoring (معیار ۴) و «استفاده خلاقانه از Agentic» (معیار ۳) را می‌گیرد. یک کار، دو معیار.

## بخش ۹ — دام‌هایی که تیم‌ها را زمین می‌زند

| # | دام | چرا کشنده است |
|---|---|---|
| ۱ | Chunking کور (تقسیم هر N کاراکتر) | بلوک کد و جدول‌های `liara.json` نصف می‌شوند → دستور ناقص → پاسخ ساختگی |
| ۲ | فقط vector search | کوئری‌ها پر از توکن دقیق‌اند (`ECONNRESET`، `DISABLE_COLLECT_STATIC`، `liara.json`)؛ embedding فارسی این‌ها را گم می‌کند، BM25 نمی‌کند |
| ۳ | توهم در جزئیات عملیاتی | نام فیلد در liara.json، نسخه‌ی Node، پورت پیش‌فرض — اشتباه = پاسخ نادرست از دید داور |
| ۴ | نداشتن حالت «نمی‌دانم» | RAG معمولی وقتی چیزی پیدا نکند از خودش می‌سازد. یک «نمی‌دانم» درست بیشتر از ده جواب پرحرف امتیاز می‌آورد |
| ۵ | سؤال چندسرویسی | «جنگو + پستگرس + دامنه» = ۳ صفحه از ۳ سرویس؛ single-shot retrieval شکست می‌خورد |
| ۶ | RTL/فارسی خراب | مخلوط فارسی-انگلیسی، بلوک کد LTR داخل متن RTL، اعداد فارسی — ۵۵ امتیاز UI را نصف می‌کند |
| ۷ | استریم تست‌نشده روی PaaS | SSE پشت پروکسی ممکن است قطع شود؛ ۳۰ ثانیه سکوت = UX نابود |
| ۸ | دیپلوی در ساعت آخر | ۴۰ امتیاز باینری؛ اولین کار، نه آخرین |
